# Covenant Agent — архитектура

Агент проверки банковских ковенантов по архиву документов и реестру транзакций.
Выход: `submission.json` по шаблону + `trace.json` для отладки.

Переписано 6 августа по факту полного разбора открытого датасета.
Числа в тексте измерены, не оценены.

---

## 0. Принципы

1. **LLM извлекает, код решает.** Модель возвращает дословные фрагменты;
   арифметика, сравнения, агрегации — Python.
2. **Ни одного числа без источника.** Документ, страница, цитата.
3. **Статус считается по неокруглённому значению.** Округление только на выводе.
4. **Порог никогда не хардкодится.** Каждый порог читается из своего документа.
5. **Три модальности чтения.** Текстовый слой, страница-картинка, документ-скан.
   Детектор работает постранично.
6. **Детерминизм.** `temperature=0`, кэш по хешу промпта, версии в манифест.
7. **Никогда не пусто.** Пустая ячейка = 0, лестница деградации обязательна.
8. **Ничего не выбрасывать молча.** Нераспознанное попадает в список, а не в `/dev/null`.

## 1. Доменная модель

```python
@dataclass(frozen=True)
class Provenance:
    doc_id: str
    page: int
    quote: str
    source_kind: str          # "text" | "ocr"
    extractor: str

@dataclass(frozen=True)
class CategorySpec:
    """Что входит в статью. Определяется ковенантом, не глобальным словарём."""
    include_keywords: list[str]
    exclude_keywords: list[str]
    sign: str                 # OUTFLOW | INFLOW | BOTH
    apply_reclass: bool = True

@dataclass(frozen=True)
class MetricSpec:
    kind: str                 # RATIO | SUM
    numerator: CategorySpec
    denominator: CategorySpec | None
    scope: str                # BORROWER | GROUP
    notes: str                # дословная формулировка

@dataclass(frozen=True)
class SpringingCondition:
    metric: MetricSpec
    operator: str
    value: Decimal
    source: Provenance

@dataclass(frozen=True)
class Covenant:
    scenario_id: str
    slot: str                 # "6.1" | "6.2" | "6.3"
    title: str
    direction: str            # MAX (≤ порога) | MIN (≥ порога)
    threshold: Decimal
    threshold_unit: str       # USD | RATIO
    metric: MetricSpec
    period: tuple[date, date]
    springing: SpringingCondition | None
    source: Provenance

@dataclass(frozen=True)
class ClassificationRule:
    """Правило из KYC-досье. Семантика различается между заёмщиками."""
    semantics: str            # RELATED_PARTY | UNRESTRICTED_SUBSIDIARY
    threshold_pct: Decimal
    direction: str            # AT_OR_ABOVE | BELOW
    source: Provenance

@dataclass(frozen=True)
class ClassifiedEntity:
    counterparty: str
    pct: Decimal
    qualifies: bool           # по правилу выше
    source: Provenance

@dataclass(frozen=True)
class Adjustment:
    kind: str                 # RECLASS | CUTOFF | EXCLUDE | OFF_LEDGER
                              # | AMOUNT_FILL | FX | EBITDA_ADDBACK | NONE
    scenario_id: str
    txn_id: str | None
    amount: Decimal | None
    counterparty: str | None
    from_category: str | None
    to_category: str | None
    floor: Decimal | None     # для EBITDA_ADDBACK
    rows: list[dict] | None   # для EBITDA_ADDBACK
    rate: Decimal | None      # для FX
    match_method: str         # txn_id | amount+counterparty | none
    source: Provenance
```

Восемь видов корректировок и две семантики KYC-таблицы — это не запас на
будущее, а измеренная реальность открытого набора.

## 2. Конвейер

```
data/{open|private}/
├─ 00_manifest.json      прогон: git sha, модели, хеш входа, тайминги
├─ 01_inventory.json     текст постранично + ocr_pages
├─ 02_classified.json    тип документа, ACC-id
├─ 03_bound.json         сценарий → его документы
├─ 04a_covenants.json    36 ковенантов
├─ 04b_parties.json      таблицы классификации + правила
├─ 04c_adjustments.json  корректировки + unrecognised
├─ 05_ledger.parquet     отфильтрован, скорректирован, в USD
├─ 06_evaluated.json     вердикты, значения, улики
├─ trace.json
└─ submission.json
```

Каждая стадия читает артефакт и пишет артефакт. Оркестратор пропускает стадию,
если её выход уже на диске — **правка кода требует `--force`**, иначе изменение
молча не применится.

---

### Стадия 1 — Ingest

Обход директории. По каждому PDF: `sha256`, число страниц, текст постранично
через `pdfplumber`.

`.txt` и `.csv` внутри папки документов читаются в тот же инвентарь: в открытом
наборе `.txt` несёт правило о действующей редакции. Нечитаемые типы
(`Thumbs.db`, бинарники, битые PDF) — в список `unreadable`, без исключения.

**Детекция картинок постраничная.** Страница, где текста меньше 100 символов
и присутствует изображение, рендерится в PNG при 150 DPI, путь и номер страницы
пишутся в `ocr_pages`.

Гейт по первой странице не работает: у аудиторского дела P4 на первой странице
2298 символов и две страницы-картинки в середине; у досье P2 и P9 текстовые все
страницы кроме одной. Всего семь таких страниц в четырёх документах, и каждая
несёт ключевое содержимое.

### Стадия 2 — Classify

Имена файлов — хеши. Классификация только по содержимому, первый совпавший
маркер выигрывает:

```
SUPERSEDED_DRAFT   ЗАМЕНЕНА ОКОНЧАТЕЛЬНЫМ | ПРОЕКТ | не может служить основанием
LOAN_SUPERSEDED    НЕ ПРИМЕНЯЕТСЯ | НЕДЕЙСТВУЮЩАЯ РЕДАКЦИЯ
LOAN               ИСПОЛНИТЕЛЬНЫЙ ЭКЗЕМПЛЯР | Старший обеспеченный заём
AUDIT_NOTES        АУДИТОРСКОЕ ДЕЛО | Примечания к финансовой отчётности
KYC                Знай своего клиента | НАДЛЕЖАЩАЯ ПРОВЕРКА КЛИЕНТА
ADJUSTMENT_SOURCE  Отчёт о выполнении согласованных процедур
                   | Служебная записка казначейства
AUDIT_PLANNING     Внешний аудит — Записка о планировании
NOISE              всё остальное
```

**Порядок несёт две ловушки.**

`SUPERSEDED_DRAFT` проверяется первым: пять документов содержат правдоподобные
нумерованные корректировки и все пять отменены, тогда как настоящая записка
казначейства помечена «РАБОЧИЙ ДОКУМЕНТ» и несёт реальную корректировку.
Дисклеймерный блок, а не ярлык рабочего документа, — разделитель.

`LOAN_SUPERSEDED` проверяется перед `LOAN`.

`AUDIT_PLANNING` классифицируется явно и затем исключается из извлечения фактов:
документ выглядит авторитетно, но текстом заявляет, что не содержит проверенных
цифр.

Ожидаемое распределение на открытом наборе: 138 NOISE, 12 LOAN,
12 LOAN_SUPERSEDED, 12 AUDIT_NOTES, 11 KYC, 8 AUDIT_PLANNING,
5 SUPERSEDED_DRAFT, 2 ADJUSTMENT_SOURCE.

### Стадия 3 — Bind

Карта `scenario_id → {loan, audit_notes, kyc, adjustment_sources}`.

Счёт выводится из леджера: префикс `txn_id` — это `scenario_id`, `account_id`
в той же строке.

```python
acc2scen = (ledger.assign(sc=ledger.txn_id.str.split("-").str[1])
                  .groupby("account_id").sc.agg(lambda s: s.mode()[0]).to_dict())
```

**По названию компании не связывать никогда:** в наборе есть
*Shymkent Refinery Services JSC* и *Shymkent Refinery JSC*,
*Ekibastuz Power Services JSC* и *Ekibastuz Energy JSC*.

KYC-досье привязывается к счёту из **шапки** (`Счёт ACC-....`), а не к любому
`ACC-` в теле: другие документы ссылаются на счета мимоходом.

Инвариант: ровно один действующий договор на сценарий.

### Стадия 4a — Ковенанты

Из действующего договора вырезать Статью 6, разбить по маркеру `Пункт 6.N`,
каждый пункт — в модель под схему `Covenant`.

**Заголовок «Статья 6» встречается дважды:** в оглавлении без тире и как
настоящий заголовок с длинным тире (`Статья 6 — Финансовые ковенанты`). Брать
последнее вхождение, иначе вырежется кусок оглавления — тихо, без ошибки.

`direction` — отдельное обязательное поле, а не вывод из названия. Слот 6.2
встречается и как MIN (минимальная выручка), и как MAX (максимальные расходы
по категории).

Ковенантный период обязан быть 2025-01-01…2025-12-31. Иначе — `PERIOD_MISMATCH`:
скорее всего просочился устаревший договор.

Каждая цитата верифицируется как подстрока текста страницы.

### Стадия 4b — Таблицы классификации

Досье содержит ту таблицу, которая нужна ковенантам этого заёмщика.
Фиксированной схемы нет:

| Семантика | Таблица | Правило |
|---|---|---|
| `RELATED_PARTY` | доли голосующих прав | ≥ порога → связанная сторона |
| `UNRESTRICTED_SUBSIDIARY` | доля активов в залоге | < порога → неограниченная |

Извлекается **таблица вместе с правилом-предложением под ней**, семантика
пишется в поле. Пороги измерены: 25.0, 35.0, 40.0 для связанности, 50.0 для
периметра обеспечения. Каждый читается из своего документа.

Сравнение точное, без округления. Сущности у самого порога — приманки, и они
вооружены: у P6 связанная сторона с 46.8% платит 418 662.44, а приманка с 38.1%
платит 4 204 663.19, в десять раз больше.

**Три досье держат таблицу на странице-картинке.** Когда стадия 1 записала
`ocr_pages`, эти страницы уходят в vision-модель под ту же схему. Верификация
цитаты к картинке неприменима: поля помечаются `source_kind="ocr"`, уверенность
понижается, запись идёт в список на просмотр.

**Нормализация имён** обязана снимать: регистр, лишние пробелы, кавычки и
ёлочки, точечные формы юрлица (`L.L.P.` наравне с `LLP`), запятую перед
суффиксом, точку в конце. Леджер и досье пишут одну сущность по-разному —
`Aktau Holdings L.L.P.` против `Aktau Holdings LLP`, «Turan Capital» LLP,
`Sarybel Capital LLP.`, `Ertis Capital, LLP`.

Нечёткое сопоставление, edit distance и вхождение подстроки — **запрещены**:
в наборе есть разные сущности с близкими именами.

Связанность по описанию транзакции неопределима: платежи выглядят как
«Management advisory retainer».

### Стадия 4c — Корректировки

Источники: `AUDIT_NOTES` и `ADJUSTMENT_SOURCE`. `SUPERSEDED_DRAFT` и
`AUDIT_PLANNING` исключены.

**Два пути сегментации, оба обязательны.**

*Путь один — нумерованные пункты.* Маркеры варьируются: `(7.1)`, `(8.1)`,
`(9.1)` — номер повторяет номер примечания; записки казначейства используют
голое `(1)` без точки. Регулярка `\((\d+(?:\.\d+)?)\)`. Где есть заголовок
`ДОПОЛНЕНИЕ О СОБЛЮДЕНИИ КОВЕНАНТОВ`, извлечение ограничивается секцией после него.

*Путь два — страницы-картинки.* Часть корректировок вообще не имеет маркера и
живёт на изображении. После сегментации по маркерам каждая `ocr_page` каждого
источника уходит в vision-модель.

**Восемь видов:**

| Вид | Что делает с леджером |
|---|---|
| `RECLASS` | меняет категорию строки |
| `CUTOFF` | помечает строку исключённой (услуги вне периода) |
| `EXCLUDE` | помечает строку исключённой |
| `OFF_LEDGER` | добавляет синтетическую строку без `txn_id` |
| `AMOUNT_FILL` | заполняет пустой `amount` существующей строки |
| `FX` | даёт курс для пересчёта |
| `EBITDA_ADDBACK` | возвращает статьи выше порога в числитель |
| `NONE` | ничего, но записывается |

`OFF_LEDGER` и `AMOUNT_FILL` различаются принципиально: первая создаёт строку,
которой нет, вторая правит существующую и **сохраняет реальный `txn_id`**, что
делает её кандидатом в улики. Две строки открытого набора имеют пустой `amount`.

`EBITDA_ADDBACK` — таблица «статья / контрагент / сумма» плюс предложение с
порогом существенности. Строки на пороге и выше возвращаются в числитель, ниже —
приманки. Привязка к транзакции по точной сумме и нормализованному контрагенту.

`FX` не имеет таблицы курсов. Раскрывается расчёт: счёт 72 146.75 EUR оплачен
$83 690.23 → курс выводится делением.

Корректировка может быть задана суммой и контрагентом вместо `txn_id`. Тогда
привязка по точному совпадению суммы и нормализованного имени; ноль или больше
одного совпадения → `AMBIGUOUS_RECLASS_MATCH`, `matched_txn = null`.

`NONE` записывается и не применяется. Всё, что классификатор не смог отнести
ни к одному виду, идёт в список `unrecognised` — **никогда не отбрасывается**.
Приватный набор может содержать девятый вид, и молчаливый пропуск — это способ
его не заметить.

### Стадия 5 — Леджер

```
фильтр по account_id сценария          673 из 1473 строк
    ↓
AMOUNT_FILL                            заполнить пустые amount
    ↓
EXCLUDE и CUTOFF                       пометить excluded
    ↓
RECLASS                                сменить категорию
    ↓
FX                                     пересчёт по выведенному курсу
    ↓
OFF_LEDGER                             добавить синтетические строки
```

Порядок важен: `AMOUNT_FILL` первым, иначе строка с пустой суммой не попадёт
ни в один агрегат и исчезнет бесследно.

Колонки результата: `txn_id, date, counterparty, description, amount_usd,
category, excluded, synthetic, adjustment_ref`.

**Инвариант: после применения корректировок ни одна строка не должна иметь
пустой `amount`.** Пустое значение молча выпадает из любого агрегата — падать
громко.

Глобальной таксономии категорий нет: принадлежность строки к статье решается
при расчёте конкретного ковенанта по его собственному определению. Одна строка
может считаться в разные статьи у разных ковенантов.

### Стадия 6 — Оценка

```python
def evaluate(cov, ledger, entities, adjustments) -> Finding:
    # 1. Шлюз применимости
    if cov.springing:
        trigger = compute(cov.springing.metric, ledger, entities)
        if not compare(trigger, cov.springing.operator, cov.springing.value):
            return Finding(status="COMPLIANT",
                           evaluated=compute(cov.metric, ledger, entities),
                           evidence=None, strategy="springing_not_triggered")

    # 2. Полная точность
    actual = compute(cov.metric, ledger, entities)      # Decimal

    # 3. Сравнение ДО округления
    status = "BREACH" if breaches(actual, cov.direction, cov.threshold) else "COMPLIANT"

    # 4. Улика — только для нарушений
    evidence = find_evidence(cov, ledger, status) if status == "BREACH" else None

    # 5. Округление только на выводе, значение всегда положительное
    return Finding(status, evaluated=actual,
                   rounded=round_half_up(abs(actual), 2), evidence=evidence)
```

**Springing при невыполненном условии:** `actual` — по-прежнему фактическое
значение показателя, оно может законно превышать лимит при статусе COMPLIANT.
Не `null` и не значение триггера.

**Сравнение до округления обязательно.** Две ячейки открытого набора имеют
одинаковый порог 0.04 и одинаковый округлённый факт 0.04 при противоположных
вердиктах.

#### Улика — контрфактуал

Улика это транзакция, чьё удаление меняет вердикт. Не крупнейшая, не последняя,
не та, что перебросила накопленную сумму за порог — кейс называет running sum
прямо неверным подходом.

```python
def find_evidence(cov, ledger, status):
    flips = [t.txn_id for t in ledger[relevant_to(cov)].itertuples()
             if verdict(compute(cov.metric, ledger.drop(t.Index)), cov) != status]
    if len(flips) == 1:
        return flips[0]
    if len(flips) > 1:
        adj = [t for t in flips if t in adjusted_txn_ids]
        return adj[0] if len(adj) == 1 else None      # + MULTIPLE_FLIPPING_TXNS
    return None
```

Приоритет транзакциям, затронутым корректировкой, — не эвристика: улика P2 6.1
это ровно та сумма, которую аудитор переклассифицировал.

Инвариант: улика непустая ⟹ статус BREACH. Обратное неверно. Слот 6.2 улик
не имеет.

#### Лестница деградации

| Поле | Ступени |
|---|---|
| `status` | посчитан → приор по слоту (6.1 BREACH, 6.2 COMPLIANT, 6.3 COMPLIANT) |
| `actual` | посчитан → значение порога → 0 |
| `evidence` | контрфактуал → `null` |

Сработавшая ступень пишется в `strategy`. `null` в улике безопасен: там, где
ключ ждёт `null`, присланное значение не оценивается.

### Стадия 7 — Emit + Validate

`submission.json = project(trace)` — чистая функция, ноль вызовов моделей.
Шаблон заполняется на месте: ключи не переименовывать, не добавлять, не удалять.

Инварианты, при нарушении которых стадия падает громко:

- ключи идентичны шаблону, число ячеек совпадает
- `status` строго `"COMPLIANT"` или `"BREACH"`
- `actual` — положительное число с двумя знаками
- `evidence_txn_id` существует в леджере либо `null`
- улика непустая ⟹ BREACH
- каждый порог имеет верифицированную цитату
- каждый ковенантный период = 2025
- ни одной строки леджера с пустым `amount`
- список `unrecognised` присутствует в выводе (пустой — нормально, отсутствующий — нет)

## 3. Локальный скорер

```python
def score_cell(ans, key) -> float:
    if ans.get("status") != key["status"]:
        return 0.0                                   # вентиль
    e = rel_err(ans.get("actual"), key["actual"])    # None → 1.0
    s = 0.50 + 0.30 * max(0.0, 1 - e / 0.05)
    if key["evidence_txn_id"] is None:
        s += 0.20 * max(0.0, 1 - e / 0.05)           # висит на actual
    elif ans.get("evidence_txn_id") == key["evidence_txn_id"]:
        s += 0.20
    return s
```

Отчёт печатается покомпонентно и по слотам: общий процент прячет, что сломано.

Абляции для понимания цены блоков: без корректировок, без OCR-ветки, без KYC,
без springing.

- Мультиагентная оркестрация, LangGraph — семь функций и цикл.
- Дообучение — нет данных, не то узкое место.
- Нечёткое сопоставление имён — в наборе близкие имена у разных сущностей.
- Глобальный словарь категорий — категория определяется ковенантом.
- Округление перед сравнением — теряет пограничные ячейки.
- Гейт OCR по первой странице — пропускает пять страниц из семи.
- Опора только на маркеры `(N.N)` — `EBITDA_ADDBACK` их не имеет.
- Фронтенд до 9 августа.

## 5. Структура репозитория

```
covenant-agent/
├─ README.md                 одна команда + раздел про модели
├─ agent/
│  ├─ __main__.py            оркестратор, --force, дедлайн-сторож
│  ├─ config.py
│  ├─ models.py              доменная модель
│  ├─ stages/s1…s7
│  ├─ parsing/               pdf, numbers, tables, names
│  ├─ llm/                   клиент с кэшем, vision, схемы
│  ├─ evidence/              верификация цитат, контрфактуал
│  └─ validate.py
├─ eval/  ground_truth.json, score.py

```

Фронтенд — вне `agent/`. Баг во фронте не может уронить сдачу.
