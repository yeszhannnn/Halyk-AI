# Covenant Agent — архитектура

Агент проверки банковских ковенантов по архиву документов и реестру транзакций.
Выход: `submission.json` по шаблону + `trace.json` для отладки.

Переписано 6 августа по факту разбора открытого датасета.

---

## 0. Принципы

1. **LLM извлекает, код решает.** Модель возвращает только то, что дословно
   написано. Арифметика, сравнения, агрегации — Python.
2. **Ни одного числа без источника.** Документ, страница, дословная цитата.
3. **Статус считается по неокруглённому значению.** Округление — только
   на выводе. Доказано на P4/P8: одинаковый порог 0.04, одинаковый
   округлённый факт 0.04, противоположные вердикты.
4. **Детерминизм.** `temperature=0`, кэш по хешу промпта, версии в манифест.
5. **Постадийная материализация.** Каждая стадия пишет артефакт.
6. **Никогда не пусто.** Пустая ячейка = 0. Лестница деградации обязательна.
7. **Порог никогда не хардкодится.** Каждый порог и каждое определение
   читаются из договора конкретного заёмщика.

## 1. Доменная модель

```python
@dataclass(frozen=True)
class Provenance:
    doc_id: str
    page: int
    quote: str                    # дословно, верифицируется как подстрока
    extractor: str

@dataclass(frozen=True)
class MetricSpec:
    """Как считать показатель. Определение живёт в тексте ковенанта."""
    kind: str                     # RATIO | SUM | COUNT
    numerator: "CategorySpec"
    denominator: "CategorySpec | None"
    scope: str                    # BORROWER | GROUP
    notes: str                    # дословная формулировка из договора

@dataclass(frozen=True)
class CategorySpec:
    """Что входит в статью. Определяется ковенантом, не глобальным словарём."""
    include_keywords: list[str]
    exclude_keywords: list[str]
    sign: str                     # OUTFLOW | INFLOW | BOTH
    apply_reclass: bool = True    # учитывать переклассификации аудитора

@dataclass(frozen=True)
class Covenant:
    scenario_id: str              # P1 … P10, B1, B4
    slot: str                     # "6.1" | "6.2" | "6.3"
    title: str
    direction: str                # MAX (≤ порога) | MIN (≥ порога)
    threshold: Decimal
    threshold_unit: str           # USD | RATIO
    metric: MetricSpec
    period: tuple[date, date]     # ковенантный период из договора
    springing: "SpringingCondition | None"
    source: Provenance

@dataclass(frozen=True)
class SpringingCondition:
    """Ковенант применяется только при выполнении условия."""
    metric: MetricSpec
    operator: str                 # ">" | "<"
    value: Decimal
    source: Provenance

@dataclass(frozen=True)
class RelatedParty:
    counterparty: str
    ownership_pct: Decimal
    is_related: bool              # ownership_pct >= порога из досье
    source: Provenance

@dataclass(frozen=True)
class Adjustment:
    """Корректировка из примечаний аудитора. Пять видов."""
    kind: str                     # RECLASS | CUTOFF | EXCLUDE | OFF_LEDGER | FX
    scenario_id: str
    txn_id: str | None            # если привязана к операции
    amount: Decimal | None        # если задана суммой + контрагентом
    counterparty: str | None
    from_category: str | None
    to_category: str | None
    source: Provenance
```

**Ключевое отличие от первой версии:** нет `ClauseVersion` с битемпоральными
интервалами. Редакция определяется одним флагом. Освободившееся место занял
`Adjustment` — вот где настоящая сложность.

Семь стадий, каждая пишет артефакт на диск.

```

├─ 01_inventory.json     файлы, страницы, текст постранично
```

### Стадия 1 — Ingest

Распаковать, обойти файлы. Для каждого PDF: `sha256`, число страниц,
текст постранично через `pdfplumber`. Ноль вызовов модели.

Не-PDF файлы (`.db`, `.txt`, `.csv` внутри папки документов) — не отбрасывать
слепо: в открытом наборе `.txt` оказался README с правилом версионности.
Прочитать, положить в инвентарь, дальше классифицировать как обычный документ.

Файлы без текстового слоя помечать `needs_ocr`. В открытом наборе такой один —
проверить, не является ли он шумом, прежде чем поднимать OCR.

---

### Стадия 2 — Classify

**Имена файлов — хеши, сигнала не несут.** Классификация только по содержимому.

Правила по маркерам в тексте, в порядке проверки:

```python
MARKERS = [
    ("LOAN_SUPERSEDED", r"НЕ ПРИМЕНЯЕТСЯ|НЕДЕЙСТВУЮЩАЯ РЕДАКЦИЯ"),
    ("LOAN",            r"ИСПОЛНИТЕЛЬНЫЙ ЭКЗЕМПЛЯР|Старший обеспеченный заём"),
    ("AUDIT_NOTES",     r"АУДИТОРСКОЕ ДЕЛО|Примечания к финансовой отчётности"),
    ("KYC",             r"Знай своего клиента|НАДЛЕЖАЩАЯ ПРОВЕРКА КЛИЕНТА"),
    ("AUDIT_PLANNING",  r"Внешний аудит — Записка о планировании"),   # ПРИМАНКА
]
```

Порядок важен: маркер устаревшей редакции проверяется **до** маркера договора.

`AUDIT_PLANNING` классифицируется явно и явно **исключается** из источников
фактов. Документ авторитетно выглядит, но текстом сам заявляет, что не содержит
проверенных цифр и что действующие раскрытия лежат в итоговых подписанных
документах. Не молча игнорировать — пометить, чтобы было видно в трейсе.

Всё, что не совпало ни с одним маркером → `NOISE`. В открытом наборе это 145
из 200. Ожидай ту же долю.

Из каждого документа извлечь `ACC-\d+` регуляркой. Если не нашлось —
пометить `unbound`.

**Проверка полноты:** число документов типа `LOAN` без флага устаревшей
должно равняться числу сценариев. Не равно — громкое предупреждение.

### Стадия 3 — Bind

Построить карту `scenario_id → {loan, audit_notes, kyc}`.

Связка через леджер, детерминированно:

```python
# префикс txn_id = scenario_id; account_id из той же строки
acc2scen = (ledger.assign(sc=ledger.txn_id.str.split("-").str[1])

```

Названия компаний **не использовать**: в наборе есть
*Shymkent Refinery Services JSC* и *Shymkent Refinery JSC*,
*Ekibastuz Power Services JSC* и *Ekibastuz Energy JSC*.
Только `ACC-`.

Инвариант: у каждого сценария ровно один действующий договор.

### Стадия 4a — Извлечение ковенантов

Из действующего договора вырезать Статью 6, разбить на пункты, каждый
отправить в модель под Pydantic-схему `Covenant`.

Что обязано вернуться дословной цитатой: порог, направление сравнения,
формулировка показателя, ковенантный период, springing-условие если есть.

**Направление сравнения — отдельное поле, не выводится из названия.**
Слот 6.2 бывает и «минимальная выручка» (MIN), и «максимальные расходы»
по категории (MAX). Спутать направление = обнулить ячейку.

**Проверка периода.** Извлечённый период должен быть 2025-01-01…2025-12-31.
Не совпал — скорее всего взят устаревший договор, поднять ошибку.

Верификация цитаты как подстроки текста страницы; не прошла — ретрай,
после двух неудач `unverified` и деградация.

### Стадия 4b — Связанные стороны

Из KYC-досье извлечь таблицу долей участия и **порог из текста досье**:

```
Pavlodar Plant Services LLP    33.8%
Sarybel Capital LLP            41.2%   ← связанная
Ural Turbine Works LLP          9.4%
«Организации, в которых Группа владеет 35.0% и более
 голосующих прав, признаются связанными сторонами»
```

Порог **не хардкодить** — он написан в досье и может отличаться у заёмщиков.
33.8% в примере — намеренная приманка.

Определить связанность по описанию транзакции невозможно: платежи проходят
как «Management advisory retainer» и «Advisory engagement on …» и внешне
неотличимы от обычных консультационных услуг. Единственный признак —
совпадение контрагента со списком.

Сопоставление имён контрагентов делать нормализованным (регистр, пробелы,
организационная форма), но **без нечёткого поиска** — в наборе есть близкие
названия у разных сущностей.

### Стадия 4c — Корректировки

Самая ценная стадия. Источник — только `AUDIT_NOTES`.

Пять видов, каждый встречается в открытом наборе:

| Вид | Пример из данных | Эффект |
|---|---|---|
| `RECLASS` | $1 104 663.28 контрагенту Tien Shan Advisory Bureau: консультационные → операционные расходы | сумма меняет статью |
| `CUTOFF` | `TXN-P1-0045` (счёт 2025-08-12) относится к услугам 2026 года | исключить из периода |
| `EXCLUDE` | `TXN-B4-0026` от 2025-11-20 исключена из ковенантного периода | исключить |
| `OFF_LEDGER` | обязательство $918 447.52 раскрыто, отдельной операцией не отражено | **добавить сумму, которой нет в CSV** |
| `FX` | 72 146.75 EUR урегулировано платежом $83 690.23 | вывести курс делением |

Корректировки нумерованы в тексте как `(7.1)`, `(9.1)` и т.п. — извлекать
по этому маркеру, затем каждую в схему `Adjustment`.

Заголовки примечаний, где они живут: «Переклассификации для целей соблюдения
ковенантов», «Отсечение и начисления», «Суммы, не отражённые в выгрузке
реестра», «Валютные курсы», «Корректировки EBITDA», «Раскрытия для
агрегирования ковенантов».

`RECLASS` бывает задан **суммой и контрагентом**, а не `txn_id` — тогда
привязка к операции ищется по совпадению суммы и контрагента в леджере
этого заёмщика. Не нашлось однозначно — в конфликты.

`OFF_LEDGER` не привязывается к операции вообще: это слагаемое,
добавляемое к агрегату.

### Стадия 5 — Леджер

```
отфильтровать по account_id сценария     (673 из 1473 строк в открытом наборе)
    ↓
применить EXCLUDE и CUTOFF               (пометить строки исключёнными)
    ↓
применить RECLASS                        (поменять категорию строки)
    ↓
пересчитать валюту по выведенному курсу  (28 строк EUR)
    ↓
добавить OFF_LEDGER как синтетические записи с флагом
```

Результат — таблица в DuckDB с колонками `txn_id, date, counterparty,
description, amount_usd, category, excluded, synthetic, adjustment_ref`.

Категория проставляется **на этапе расчёта конкретного ковенанта**, а не
глобально: определение «операционных расходов» берётся из текста этого
ковенанта. Одна и та же строка может попасть в разные статьи у разных
ковенантов.

### Стадия 6 — Оценка

На каждый из 36 ковенантов:

```python
def evaluate(cov: Covenant, ledger, parties, adjustments) -> Finding:
    # 1. Шлюз применимости
    if cov.springing:
        trigger = compute(cov.springing.metric, ledger, parties)
        if not compare(trigger, cov.springing.operator, cov.springing.value):
            return Finding(status="COMPLIANT", actual=compute(cov.metric, ...),
                           evidence=None, strategy="springing_not_triggered")

    # 2. Расчёт в полной точности
    actual = compute(cov.metric, ledger, parties)          # Decimal

    # 3. Сравнение ДО округления
    status = "BREACH" if breaches(actual, cov.direction, cov.threshold) else "COMPLIANT"

    # 4. Улика — только для нарушений, контрфактуалом
    evidence = find_evidence(cov, ledger, actual, status) if status == "BREACH" else None

    # 5. Округление ТОЛЬКО на выводе
    return Finding(status, evaluated=actual, rounded=round_half_up(actual, 2), evidence)
```

**Springing при невыполненном условии.** По кейсу: `actual` — по-прежнему
фактическое значение показателя, оно может быть выше лимита при статусе
COMPLIANT. Не `null` и не значение условия.

#### Поиск улики — контрфактуал, не running sum

Определение из кейса: улика — та транзакция, чья переклассификация,
включение, исключение или исправление приводит к нарушению. Уберёшь её —
вердикт изменится. Транзакция, лишь вносящая вклад в сумму, уликой
**не является** — ни крупнейшая, ни последняя, ни случайно перебросившая
накопленную сумму за порог.

```python
def find_evidence(cov, ledger, actual, status):
    candidates = ledger[relevant_to(cov)]            # только релевантные ковенанту
    flips = []
    for txn in candidates.itertuples():
        alt = compute(cov.metric, ledger.drop(txn.Index), parties)
        if verdict(alt, cov) != status:
            flips.append(txn.txn_id)
    if len(flips) == 1:
        return flips[0]
    if len(flips) > 1:
        # приоритет транзакциям, затронутым корректировкой аудитора
        adj = [t for t in flips if t in adjusted_txn_ids]
        return adj[0] if len(adj) == 1 else None
    return None
```

Приоритет скорректированным транзакциям — не эвристика: в открытом наборе
улика для P2 6.1 (`TXN-P2-0040`) это ровно та сумма, которую аудитор
переклассифицировал.

Инвариант: улика непустая ⟹ статус BREACH. Обратное неверно.
Слот 6.2 улик не имеет.

#### Лестница деградации

Порядок до первого успеха, каждая ступень пишется в `strategy`:

**status:** посчитан → приор по слоту (6.1 BREACH, 6.2 COMPLIANT, 6.3 COMPLIANT)
**actual:** посчитан → значение порога (даёт «на грани», при относительной
шкале часто попадает в 5%) → 0
**evidence:** контрфактуал → `null`

`null` в улике безопасен: в ячейках, где ключ ждёт `null`, присланное
значение не оценивается вовсе.

### Стадия 7 — Emit + Validate

`submission.json = project(trace)` — чистая функция, никаких вызовов моделей.

```python
{
  "team": ..., "contact_email": ..., "model": ...,
  "answers": { "P1": { "6.1": {"status": "BREACH",
                               "actual": 0.46,
                               "evidence_txn_id": None}, ... }, ... }
}
```

Инварианты, при нарушении которых стадия падает громко:

- Ключи ровно как в `submission_template.json` — не переименованы,
  не добавлены, не удалены
- `status` строго `"COMPLIANT"` или `"BREACH"`
- `actual` — число, положительное, два знака после запятой
- `evidence_txn_id` существует в леджере либо `null`
- Улика непустая ⟹ статус BREACH
- Каждый порог имеет верифицированную цитату-источник
- Ковенантный период каждого договора = 2025
- Ни одной ячейки со `strategy == "fallback"` без записи в список на просмотр

**Знак.** `actual` всегда положительный, включая расходы: в леджере списания
отрицательные, в ответ идёт модуль. Забытый `abs()` даёт относительную
погрешность 2.0 и обнуляет все расходные ячейки разом.

## 3. Локальный скорер

Единственный контур обратной связи. Реализует формулу организаторов
поверх `ground_truth.json` открытого набора.

```python
def score_cell(ans, key) -> float:
    if ans.get("status") != key["status"]:
        return 0.0                                   # вентиль
    s = 0.50
    e = rel_err(ans.get("actual"), key["actual"])     # None → 1.0
    a = 0.30 * max(0.0, 1 - e / 0.05)
    s += a
    if key["evidence_txn_id"] is None:
        s += 0.20 * max(0.0, 1 - e / 0.05)            # висит на actual
    elif ans.get("evidence_txn_id") == key["evidence_txn_id"]:
        s += 0.20
    return s
```

Отчёт печатать **покомпонентно и по слотам**, а не одним числом:
общий процент прячет, что именно сломано.

Абляции, которые стоит гонять: без корректировок, без KYC, без springing.
Разница показывает цену каждого блока и говорит, куда вкладывать время.

## 4. Чего не делать

- **Векторная база.** 200 документов, маркерная классификация точнее
  и детерминирована.
- **Мультиагентная оркестрация, LangGraph.** Семь функций и цикл.
- **Дообучение.** Нет размеченных данных, не то узкое место.
- **VLM ради координат.** Текстовый слой есть везде.
- **Нечёткое сопоставление имён компаний.** В наборе близкие названия
  у разных сущностей — нечёткий поиск создаст ошибки.
- **Глобальный словарь категорий.** Категория определяется ковенантом.
- **Округление перед сравнением.** Обнуляет ячейки на границе.
- **Фронтенд до 9 августа.**
